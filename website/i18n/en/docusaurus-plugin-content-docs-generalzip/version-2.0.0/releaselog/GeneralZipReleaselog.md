# 📒Release log

### 📍2026-11-20 — v2.0.0 capability expansion (unreleased)

*These changes are merged to the [`main` branch of the GeneralZip repository](https://github.com/GeneralLibrary/GeneralZip) (PR #1, PR #2); the component version has moved to `2.0.0` but no release tag has been cut yet — the NuGet version will be noted here once published.*

- **Implicit bootstrap (breaking refactor)**: the Rust native core is now assembled automatically when `GeneralZipFormatRegistry.Default` is first constructed — the core is loaded, 7z/RAR providers are registered per capability bits, and the native codec delegates are injected; custom registries are covered by the codec router's `EnsureBridge()` fallback. `GeneralZip.Initialize()` and `GeneralZipNative.Initialize()` have been removed — use `NativeCoreLoader.TryLoad()` to probe core availability
- **One-line archive operations**: the facade gains `Append/AppendAsync` (append entries to an existing ZIP archive), `Remove/RemoveAsync` (delete entries by name) and `Convert/ConvertAsync` (cross-format conversion) — read→rewrite semantics; converting an encrypted archive automatically inherits its algorithm and password, never silently producing a plaintext output
- **Stream-to-stream overloads**: `Compress` / `Extract` / `Test` gain Stream→Stream overloads — compress, extract, and integrity-test memory/network streams without touching disk
- **Glob entry filters**: extraction gains `ExtractionOptions.IncludePatterns` / `ExcludePatterns` (`**` cross-layer matching, character classes); exclude patterns win over include patterns
- **ZIP extended compression methods**: `ArchiveWriteOptions.ZipCompressionMethod` adds BZip2 (method 12) / Zstd (method 93) / LZMA (method 14, method-14 EOPM framing), interoperable with 7-Zip / Info-ZIP; default `Auto` (Deflate)
- **Streaming native codecs**: the Rust core was rewritten to a callback push-pull FFI (`gzp_codec_crun/drun`) — bzip2/xz/zstd/lz4/brotli all transcode with zero temp files, removing the v1 "one-shot zstd API" and "temp-file full-segment transcoding" limitations
- **Parallel compress/extract**: write-side staged parallel compression and read-side per-worker archive reopen with a lock-serialized event relay, controlled by `ArchiveWriteOptions.MaxDegreeOfParallelism` / `ExtractionOptions.MaxDegreeOfParallelism` (default 1 = serial, behavior unchanged)
- **Async enumeration**: `GeneralZipAsyncExtensions.EnumerateEntriesAsync` (`IAsyncEnumerable<IArchiveEntry>`) and `ExtractEntryAsync`
- **SM2 national-crypto envelope encryption**: pure C# SM2 implementation (GB/T 32918.5 curve, ECIES C1-C3-C2), cross-validated against python gmssl in both directions with an interop anchor vector; `Sm2GmProvider` (AlgorithmId `"SM2-GM"`, extra field 0x4D54) generates a random per-entry data key sealed with the recipient's SM2 public key — a **passwordless write path** (`IPasswordlessWriteProvider`, private key delivered via the password pipeline); pass `ArchiveWriteOptions.RecipientPublicKey` and encrypt
- **Pluggable KDF registry**: new `IKdfProvider` abstraction and `ArchiveWriteOptions.KdfAlgorithmId` switch with built-in SM3-PBKDF2 (SpecId 1, default) and PBKDF2-SHA256 (SpecId 2); the SM4-GM container carries the SpecId in its extra field, keeping old archives readable
- **New formats**: CPIO (newc/odc/binary read, newc write, fully managed), ISO9660 (read-only, +Joliet/Rock Ridge), CAB (read-only, NONE-stored folders; MSZIP/LZX explicitly unsupported), Brotli (read/write, native core)
- **Split-volume ZIP**: `ArchiveWriteOptions.VolumeSize` splits output into `.001/.002/…` volumes; opening `.001` auto-concatenates the remaining volumes
- **Unix attributes & symlinks**: new `IUnixEntry` (ZIP Unix host / ustar mode) and symlink writing (ZIP `S_IFLNK` / TAR typeflag 2), with `SymlinkPolicy` (default Skip, security first) and `PreserveUnixAttributes` to keep mode bits on extraction
- **Command-line tool**: new `GeneralZip.Cli` (dotnet global tool, command name `gz`) — `a` compress / `x` extract / `t` integrity test / `l` list / `c` convert / `rm` remove entries / `i` info / `detect` format detection / `keygen` SM2 keypair generation
- **Release matrix expansion**: the native core build matrix grows from 5 RIDs to 8 (adds linux-arm64 / win-arm64 / win-x86)
- **Robustness**: new SharpFuzz fuzzing harness and `RobustnessTests` regression (random/truncated/bit-flipped inputs never crash the reader); interop fixtures generated by independent implementations (py7zr, pycdlib, python zipfile, GNU cpio newc) as read-side compatibility anchors
- **Fix**: `NativeTempDecodeStream` no longer drains and disposes the caller's source stream in its constructor (fixes `ObjectDisposedException` on non-seekable TAR.BZ2 roundtrips); transcode callback exceptions are rethrown via `ExceptionDispatchInfo`, preserving the original stack
- **Docs**: the component reference (zh/en) was updated in sync — format matrix, encryption guide, and feature list — and this release log page was added

### 📍2026-11-02 — v0.0.1-beta (first public preview)

- **Single-package architecture**: `GeneralZip.Native` merged into the `GeneralZip` package, bundling prebuilt Rust native cores for five platforms (win-x64 / linux-x64 / linux-musl-x64 / osx-x64 / osx-arm64) — loaded automatically on first use, graceful degradation when missing
- **Cross-format compression engine**: unified API with magic-byte detection across ZIP, 7z, RAR, TAR, GZ, BZ2, XZ, Zstd, and LZ4; three encryption schemes (ZipCrypto / WinZip AES / SM4-GM), with SM3/SM4/TAR/CRC32 as pure C# implementations locked by GB/T standard vectors
- **Engineering**: CI + Release pipelines (RID build matrix, NuGet/snupkg publish smoke tests), all runtime messages translated to English, cross-platform deterministic fixture anchors, READMEs rewritten after mainstream OSS conventions, 73 tests (standard vectors + interop oracle + events + fixtures)
